# [Pet20] SMADA-Fog: Semantic model driven approach to deployment and adaptivity in fog computing

- **Autores:** N. Petrovic, M. Tosic
- **Año:** 2020
- **Publicación:** Simulation Modelling Practice and Theory, artículo 102033
- **DOI:** https://doi.org/10.1016/j.simpat.2019.102033
- **PDF en Undermind:** no disponible.

## Abstract original
> The deployment, monitoring and configuration of applications in Fog Computing are becoming quite challenging, due to heterogeneity of mobile and IoT devices involved, data movement constraints imposed by legal regulations as well as frequent changes in the execution environment that may affect quality of service. As a consequence, the system administration procedures are becoming more complex and time-consuming, especially if done manually. In this paper, a Semantic Model driven Approach to Deployment and Adaptivity of container-based applications in Fog Computing (SMADA-Fog) is proposed. Modeling tools, semantic framework, linear optimization model, simulation environment and infrastructure management code generator leveraging the semantic annotations are implemented and presented. According to results of the two experimentally tested scenarios, the proposed approach improves the application performance, while the time required for deployment as well as service adaptation is reduced for at least an order of magnitude.

## Resumen analítico
Propone SMADA-Fog, un enfoque semántico basado en modelos para desplegar y adaptar aplicaciones contenerizadas en Fog Computing. Integra herramientas de modelado, un marco semántico, un modelo de optimización lineal, un entorno de simulación y un generador de código para gestionar infraestructura. La evaluación se basa en dos escenarios experimentales; el abstract informa mejoras de rendimiento y una reducción de al menos un orden de magnitud en el tiempo requerido para despliegue y adaptación de servicios.

## Aporte para la investigación
Aporta un enfoque de modelado y optimización para adaptación de servicios contenerizados en infraestructuras heterogéneas y cambiantes. Puede ayudar a identificar variables y restricciones que un modelo de asignación dinámica debería representar.

## Límite
No es una extensión UML según la información recuperada. El abstract tampoco permite determinar si el modelo representa explícitamente el historial temporal de asignaciones o si la optimización decide ubicaciones en cada evento.

## Pertinencia
**Alta para adaptación de aplicaciones contenerizadas; indirecta para UML.**
